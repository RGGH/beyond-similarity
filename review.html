Scene 07 — Review & Zoom Out

Formula Query is a ranking function you write. LTR is a ranking function the data helps you learn.

Stepping back from the mechanics to place this technique in the wider landscape of ranking.

01What Formula Query actually provides

Underneath the sliders and decay curves, Formula Query is a general-purpose way to construct a ranking expression that Qdrant evaluates at query time: an expression tree combining arithmetic operations, decay functions, $score, and payload fields, evaluated for each candidate.

The additive popularity-plus-recency formula is a simple, useful case. The same mechanism supports considerably more — nested expressions, multiple decay curves over different fields, and conditional expressions based on payload values — without having to move the ranking logic into application code.

02Beyond simple score boosting

It's tempting to think of this as "similarity plus a couple of bonus points," but the formula is really a small ranking DSL.

Decay functions alone cover a useful range of ranking behaviour:

  • Linear decay — a predictable falloff toward zero
  • Exponential decay — relevance drops off progressively with distance from a target
  • Gaussian decay — a softer preference clustered around an ideal value, rather than a simple "more is better" rule

That makes it possible to express ranking policies that would otherwise require quite a bit of application-side logic.

03Hand-designed ranking vs. learned ranking

Formula Query sits at one end of a spectrum. At the other end is Learn-to-Rank (LTR): instead of a person deciding that popularity deserves a particular weight, a model is trained from historical relevance or interaction data to learn which signals predict a desirable ranking outcome.

Those signals might include clicks, purchases, dwell time, textual relevance, popularity, recency, or many other features. A learned model can also capture interactions between signals that would be cumbersome to specify manually.

04When each approach makes sense

Reach for Formula Query when...

You're early, interaction data is thin, stakeholders need to understand and trust the ranking, or the business logic itself is simple enough to express clearly as a formula.

Reach for LTR when...

You have enough representative training data, the number of useful signals has grown beyond what is practical to weight by hand, and the expected benefit justifies the additional work of training, evaluating, and maintaining a model.

The two aren't mutually exclusive. A system can use an explicit formula for some ranking logic while also incorporating a learned model elsewhere in the ranking pipeline. An explicit Formula Query can also provide a useful, interpretable baseline against which a learned ranker can be evaluated.
