Scene 05 — Qdrant & Pseudocode

One query. Retrieval and ranking, in the same round trip.

The conceptual shape of a Formula Query

01The flow

A boosted search comprises two parts: prefetch a wide candidate set by vector similarity, then rescore that set with a formula that folds in payload signals.

prefetch Vector similarity Embed the query, retrieve a wide candidate set (e.g. top 100) by nearest neighbour
payload Business signals Pull popularity, recency and any filter fields already stored on each candidate
formula Rescore Combine similarity + weighted signals into one final_score per candidate
result Final ranking Sort by final_score, return the top N

The candidate set from the first stage is deliberately wider than what gets returned — rescoring can only reorder what it's given, so retrieval needs enough headroom for popularity and recency to meaningfully shuffle the ranking. Taken to the extreme, you couldn't have a final top 10 rankings if you only had 5 candidates to work with.

02The shape of the formula, in pseudocode

Stripped down to the concept — no client setup, no error handling, no Streamlit:

# 1. retrieve a wide candidate set by vector similarity
candidates = vector_search(query_embedding, limit=100, filter=colour_filter)

# 2. define a decay curve over the recency payload field
recency_term = decay(
    field="recency", shape="linear | exp | gauss",
    target=1.0, scale=0.5, midpoint=0.5,
)

# 3. rescore each candidate with an additive formula
final_score = sum(
    $score,                                # the original similarity
    popularity_weight * payload.popularity,
    recency_weight   * recency_term,
)

# 4. sort candidates by final_score, return the top N
results = rank_by(candidates, final_score, limit=10)

Two things worth noticing: $score is a reference to the similarity already computed in the prefetch step, not a fresh computation — the formula reuses it rather than re-deriving it, you won't see it anywhere else in the code, but it's used internally by the Qdrant code. The decay curve is just another term; swapping linear for gauss changes the shape of one input, not the structure of the formula.

03\What Qdrant is actually doing here

This runs as a single query against the database — the prefetch and the formula rescoring happen server-side, in one round trip. That matters for two reasons: the ranking logic lives next to the data it reads instead of in application code pulling every candidate back to compute a score client-side, and it stays fast enough to run per-request rather than as a batch job.
